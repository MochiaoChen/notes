## 异常值

在统计学中，异常值是指超出预期范围的数据。

通常，统计学家和数据科学家希望识别出异常值以便进行特殊处理。有时，人们希望在计算中剔除异常值。在其他情况下，你可能希望将异常值包含在分析中。

为了说明我们如何在 R 中处理异常值，你可以在 RStudio 中通过在 R 控制台输入 `file.create("temps.R")` 来创建一个新文件。此外，你需要将名为 `temps.RData` 的文件下载到你的工作目录中。下载地址在：
https://cdn.cs50.net/r/2024/x/lectures/2/src2/outliers/temps.RData

为了加载数据，我们可以编写如下代码：

```R
# 演示从 .RData 文件中加载数据

load("temps.RData")
mean(temps)
```
注意 `load` 函数如何加载我们名为 `temps.RData` 的数据文件。接下来，`mean` 将对这些数据求平均值。
运行这个脚本，你可以看到计算的结果。
然而，正如之前所述，这些底层数据中存在异常值。让我们找出它们。
纵观 `temps`，我们希望能够直接访问这些异常的温度值。
回想在第 1 周我们是如何对向量中的数据进行索引的。按如下方式修改你的代码：
```r
# 演示通过索引识别异常值

load("temps.RData")

temps[2]
temps[4]
temps[7]

temps[c(2, 4, 7)]
```
注意 `temps[2]` 将如何直接访问其中一个异常温度值。最后一行代码提取了 `temps` 向量的一个子集，该子集仅包含第 2 个、第 4 个和第 7 个索引处的元素。
作为下一步，我们可以移除异常值数据：
```r
# 演示通过索引移除异常值

load("temps.RData")
no_outliers <- temps[-c(2, 4, 7)]

mean(no_outliers)
mean(temps)
```
注意数据已被加载。然后，`no_outliers` 是一个新的向量，它仅包含那些非异常值的温度。名为 `temps` 的向量仍然包含异常值数据。
## 逻辑表达式

逻辑表达式是通过编程方式回答「是」与「否」问题的手段。逻辑表达式使用逻辑运算符，这些运算符用于比较不同的值。
你可以在 R 中使用许多逻辑运算符，包括：
```R
==
!=
>
>=
<
<=
```
例如，你可以通过在 R 控制台输入 `1 == 2` 来询问 1 是否等于 2。结果应当是 `FALSE`（或表示「否！」）。然而，`1 < 2` 应当是 `TRUE`（或表示「是！」）。
逻辑值是逻辑表达式提供的响应。逻辑值可以是 `TRUE` 或 `FALSE`。这些值也可以用更简写的形式表达为 `T` 或 `F`。
在你的代码中使用逻辑运算符，你可以将代码修改如下：
```r
# 演示使用逻辑表达式识别异常值

load("temps.RData")

temps[1] < 0
temps[2] < 0
temps[3] < 0
```
注意运行此代码将如何在 R 控制台产生以 `TRUE` 和 `FALSE` 表示的答案。
这段代码可以进一步改进如下：
```r
# 演示比较运算符是向量化的

load("temps.RData")

temps < 0
```
注意运行这段代码将如何创建一个逻辑向量（即一个包含逻辑值的向量）。该逻辑向量中的每个值都回答了其对应的值是否小于 0。
为了找出使得某个逻辑表达式为真的索引，你可以如下修改代码：
```r
# 演示使用 `which` 返回逻辑表达式为 TRUE 的索引

load("temps.RData")

which(temps < 0)
```
注意，现在向量中小于 0 的温度的索引被输出到了 R 控制台。函数 `which` 接受一个逻辑向量作为输入，并返回值为 `TRUE` 的那些索引。
在处理异常值时，一个常见的需求是展示低于或高于某个阈值的数据。你可以在代码中实现这一点如下：
```r
# 演示使用复合逻辑表达式识别异常值

load("temps.RData")
temps < 0 | temps > 60
```
注意字符 `|` 在表达式中象征着「或」。对于 `temps` 中任何小于 0 或大于 60 的值，此逻辑表达式都将为 `TRUE`。
除了我们之前讨论的逻辑运算符，我们现在在词汇表中加入两个新的运算符：
`|`
`&`
注意系统如何提供了表达「或」与「与」的能力。
你可以进一步改进你的代码如下：
```r
# 演示使用 `any` 和 `all` 来测试异常值

load("temps.RData")

any(temps < 0 | temps > 60)
all(temps < 0 | temps > 60)
```
注意 `any` 和 `all` 如何接受逻辑向量作为输入。`any` 回答了这样一个问题：「这些逻辑值中有任何一个为真吗？」。`all` 回答了这样一个问题：「这些温度是否全都为真？」。
使用逻辑向量提取子集
正如前面所展示的，我们可以按如下方式创建一个去除了异常值的新向量：
```r
# 演示使用逻辑向量对向量提取子集

load("temps.RData")
filter <- temps < 0 | temps > 60
temps[filter]
```
注意代码如何基于一个逻辑表达式创建了一个名为 `filter` 的新子集向量。因此，现在可以将 `filter` 提供给 `temps`，以请求 `temps` 中在逻辑表达式中评估为 `TRUE` 的那些项。
类似地，代码可以修改为仅过滤出那些非异常值的项：
```r
# 演示使用 ! 对逻辑表达式取反

load("temps.RData")
filter <- !(temps < 0 | temps > 60)
temps[filter]
```
注意添加的 `!` 意味着不等于或者简单地说就是「非」。
这种取反操作可以用来将异常值从数据中完全移除：
```r
# 演示移除异常值
load("temps.RData")

no_outliers <- temps[!(temps < 0 | temps > 60)]
save(no_outliers, file = "no_outliers.RData")

outliers <- temps[temps < 0 | temps > 60]
save(outliers, file = "outliers.RData")
```
注意现在保存了两个文件。一个排除了异常值。另一个包含了异常值。这些文件被保存在工作目录中。
## 数据框的子集

我们如何从数据集中找到我们感兴趣的数据子集？
想象一个数据表格，其中记录了每只小鸡（baby chicken！）、喂给每只小鸡的饲料以及每只小鸡的重量。你可以从https://cdn.cs50.net/r/2024/x/lectures/2/src2/chicks/chicks.csv?download下载 `chicks.csv` 来查看这些数据。
在 RStudio 中关闭我们之前的文件，让我们在 R 控制台中通过输入 `file.create("chicks.R")` 创建一个新文件。确保你的工作目录中有 `chicks.csv`，然后选择 `chicks.R` 并编写如下代码：
```r
# 读取数据的 CSV 文件

chicks <- read.csv("chicks.csv")
View(chicks)
```
注意 `read.csv` 将 CSV 文件读取到一个名为 `chicks` 的数据框中。然后，对 `chicks` 进行了查看。
观察上述代码的输出，请注意存在许多 `NA` 值，代表不可用的数据。考虑这可能会对计算平均小鸡重量产生何种影响。将你的代码修改如下：
```r
# 演示带有 NA 值的 `mean` 计算

chicks <- read.csv("chicks.csv")
average_weight <- mean(chicks$weight)
average_weight
```
注意运行此代码将如何导致一个错误，因为有些值无法进行数学评估。
缺失数据是统计学中一个预期会遇到的问题。作为程序员，你需要决定如何处理缺失数据。你可以按如下方式在计算小鸡平均重量时移除 `NA` 值：
```r
# 演示使用 na.rm 从平均值计算中移除 NA 值

chicks <- read.csv("chicks.csv")
average_weight <- mean(chicks$weight, na.rm = TRUE)
average_weight
```
注意 `na.rm = TRUE` 将移除所有的 `NA` 值，以便使用 `mean` 计算平均值。根据文档，`na.rm` 可以设置为 `TRUE` 或 `FALSE`。
现在，让我们弄清楚每只小鸡所吃的食物是如何影响它们的重量的：
```r
# 演示使用明确的索引计算 casein 的平均值

chicks <- read.csv("chicks.csv")
casein_chicks <- chicks[c(1, 2, 3), ]
mean(casein_chicks$weight)
```
注意通过明确指定适当的索引，创建了 `chicks` 数据框的一个子集。
这不是一种高效的编程方式，因为我们不应期望我们的数据永远不会改变。我们如何修改代码使其更具灵活性？我们可以使用逻辑表达式来动态地对数据框提取子集。
```r
# 演示使用逻辑表达式识别使用 casein 饲料的行

chicks <- read.csv("chicks.csv")

chicks$feed == "casein"
```
注意逻辑表达式如何识别 `feed` 列中的每个值是否等于「casein」。
我们可以在代码中按如下方式利用这个逻辑表达式：
```r
# 演示使用逻辑向量对数据框提取子集

chicks <- read.csv("chicks.csv")

filter <- chicks$feed == "casein"
casein_chicks <- chicks[filter, ]
mean(casein_chicks$weight)
```
正如前面所演示的，请注意如何创建了一个名为 `filter` 的逻辑向量。然后，只有那些在 `filter` 中为 `TRUE` 的行被带入到了数据框 `casein_chicks` 中。
我们现在有了数据框的一个子集。
你可以通过使用函数 `subset` 达到相同的结果：
```r
# 演示使用 `subset` 提取子集

chicks <- read.csv("chicks.csv")

casein_chicks <- subset(chicks, feed == "casein")
mean(casein_chicks$weight, na.rm = TRUE)
```
这个名为 `casein_chicks` 的数据框是通过 `subset` 函数创建的。
现在，人们可能希望在开始时过滤掉所有的 `NA` 值。考虑以下代码：
```r
# 演示使用 `is.na` 识别 NA 值

chicks <- read.csv("chicks.csv")

is.na(chicks$weight)
!is.na(chicks$weight)

chicks$chick[is.na(chicks$weight)]
```
注意这段代码将如何使用 `is.na` 来查找 `NA` 值。
可以利用 `is.na` 将记录完全移除，如下所示：
```r
# 演示移除 NA 值并重置行名

chicks <- read.csv("chicks.csv")

chicks <- subset(chicks, !is.na(weight))
rownames(chicks)

rownames(chicks) <- NULL
rownames(chicks)
```
注意这段代码如何创建了 `chicks` 的一个子集，其中 `is.na(weight)` 等于 `FALSE`。也就是说，`chicks` 仅包含 `weight` 列中不存在 `NA` 的行。不过，如果你关心数据框的行名，请注意当移除了某些行时，同时也移除了那些行对应的行名。你可以通过运行 `rownames(chicks) <- NULL` 来确保行名仍然按顺序递增，这将重置所有行的名称。
## 菜单

在 R 中，你可以向用户展示选项。例如，你可以让用户选择他们希望为小鸡过滤的饲料类型。
考虑这段代码：
```r
# 演示按饲料类型查看数据的交互式程序

# 读取和清理数据
chicks <- read.csv("chicks.csv")
chicks <- subset(chicks, !is.na(weight))

# 确定饲料选项
feed_options <- unique(chicks$feed)

# 提示用户选项
cat("1.", feed_options[1])
cat("2.", feed_options[2])
cat("3.", feed_options[3])
cat("4.", feed_options[4])
cat("5.", feed_options[5])
cat("6.", feed_options[6])
feed_choice <- as.integer(readline("Feed type: "))
```
注意这段代码如何使用 `unique` 来发现独立的唯一饲料选项。每一个饲料选项然后通过 `cat` 输出。
这段代码在展示各种饲料选项的意义上是有效的，但它的格式排版并不是很好。我们如何在 R 控制台中将不同的选项输出在各自独立的行上？
## 转义字符

转义字符是指那些输出形式不同于你输入方式的字符。
例如，一些常用的转义字符有 `\n`（打印一个换行符）或 `\t`（打印一个制表符）。
利用转义字符，我们可以如下修改代码：
```r
# 演示 \n

# 读取和清理数据
chicks <- read.csv("chicks.csv")
chicks <- subset(chicks, !is.na(weight))

# 确定饲料选项
feed_options <- unique(chicks$feed)

# 提示用户选项
cat("1.", feed_options[1], "\n")
cat("2.", feed_options[2], "\n")
cat("3.", feed_options[3], "\n")
cat("4.", feed_options[4], "\n")
cat("5.", feed_options[5], "\n")
cat("6.", feed_options[6], "\n")
feed_choice <- as.integer(readline("Feed type: "))
```
注意这如何将所有的饲料选项输出在单独的行上。
虽然我们展示了正确形式的菜单，但从设计的角度来看，我们仍然可以改进代码。例如，为什么我们要重复所有这些 `cat` 行？如下简化你的代码：
```r
# 演示按饲料类型查看数据的交互式程序

# 读取和清理数据
chicks <- read.csv("chicks.csv")
chicks <- subset(chicks, !is.na(weight))

# 确定饲料选项
feed_options <- unique(chicks$feed)

# 格式化饲料选项
formatted_options <- paste0(1:length(feed_options), ". ", feed_options)

# 提示用户选项
cat(formatted_options, sep = "\n")
feed_choice <- as.integer(readline("Feed type: "))
```
注意 `formatted_options` 如何包含所有单独的饲料选项。这个 `formatted_options` 向量的每一个元素都通过 `cat(formatted_options, sep = "\n")` 打印出来并由换行符分隔。
现在，正如我们之前指出的，我们的意图是创建一个交互式程序。因此，我们现在可以向用户提示选项：
```r
# 演示按饲料类型查看数据的交互式程序

# 读取和清理数据
chicks <- read.csv("chicks.csv")
chicks <- subset(chicks, !is.na(weight))

# 确定饲料选项
feed_options <- unique(chicks$feed)

# 格式化饲料选项
formatted_options <- paste0(1:length(feed_options), ". ", feed_options)

# 提示用户选项
cat(formatted_options, sep = "\n")
feed_choice <- as.integer(readline("Feed type: "))

# 打印选定的选项
selected_feed <- feed_options[feed_choice]
print(subset(chicks, feed == selected_feed))
```
注意系统如何向用户提示 `Feed type:`，在这里一个数字可以被转换为基于文本形式的饲料选项表示。然后，他们选择的 `feed_choice` 会被赋值给 `selected_feed`。最后，对应于 `selected_feed` 的子集会被输出给用户。
然而，你可以想象你的用户可能不会像预期的那样行事。例如，如果用户输入了 0（这不是一个潜在的选项），我们程序的输出将会很奇怪。我们如何确保用户输入了正确的文本？
## 条件语句

条件语句是决定某个条件是否已满足的方式。
考虑以下代码：
```r
# 演示按饲料类型查看数据的交互式程序

# 读取和清理数据
chicks <- read.csv("chicks.csv")
chicks <- subset(chicks, !is.na(weight))

# 确定饲料选项
feed_options <- unique(chicks$feed)

# 格式化饲料选项
formatted_options <- paste0(1:length(feed_options), ". ", feed_options)

# 提示用户选项
cat(formatted_options, sep = "\n")
feed_choice <- as.integer(readline("Feed type: "))

# 无效的选择？
if (feed_choice < 1 || feed_choice > length(feed_options)) {
  cat("Invalid choice.")
}

selected_feed <- feed_options[feed_choice]
print(subset(chicks, feed == selected_feed))
```
注意 `if (feed_choice < 1 || feed_choice > length(feed_options))` 如何确定用户的输入是否落在数值范围之外。如果是这样，程序会显示「Invalid choice.」。然而，仍然存在一个问题：即使用户输入了无效选择，程序仍将继续运行。
可以按如下方式利用 `if` 和 `else`，以便仅当用户输入了有效选择时才运行最终计算：
```r
# 演示按饲料类型查看数据的交互式程序

# 读取和清理数据
chicks <- read.csv("chicks.csv")
chicks <- subset(chicks, !is.na(weight))

# 确定饲料选项
feed_options <- unique(chicks$feed)

# 格式化饲料选项
formatted_options <- paste0(1:length(feed_options), ". ", feed_options)

# 提示用户选项
cat(formatted_options, sep = "\n")
feed_choice <- as.integer(readline("Feed type: "))

# 无效的选择？
if (feed_choice < 1 || feed_choice > length(feed_options)) {
  cat("Invalid choice.")
} else {
  selected_feed <- feed_options[feed_choice]
  print(subset(chicks, feed == selected_feed))
}
```
注意，包裹在 `if` 中的代码仅在存在无效选择时才会运行。包裹在 `else` 中的代码仅在前一个 `if` 中的条件未满足时才会运行。
## 组合数据源

作为本次讲义的最后一个主题，让我们探讨一下如何组合数据源。你可以通过 
https://cdn.cs50.net/r/2024/x/lectures/2/src2/sales/Q1.csv?download
https://cdn.cs50.net/r/2024/x/lectures/2/src2/sales/Q2.csv?download
https://cdn.cs50.net/r/2024/x/lectures/2/src2/sales/Q3.csv?download
https://cdn.cs50.net/r/2024/x/lectures/2/src2/sales/Q4.csv?download
想象一个像Amazon可能拥有的、代表向客户进行销售的数据表格。
你可以想象这些数据分散在许多表格中的场景。如何将这些来自众多来源的数据组合起来？
考虑以下名为 `sales.R` 的代码：
```r
# 读取 4 个独立的 CSV 文件

Q1 <- read.csv("Q1.csv")
Q2 <- read.csv("Q2.csv")
Q3 <- read.csv("Q3.csv")
Q4 <- read.csv("Q4.csv")
```
注意每个季度的财务数据（例如 `Q1` 和 `Q2`）如何被读取到它们各自的数据框中。
现在，让我们将这四个数据框中的数据组合起来：
```r
# 使用 `rbind` 组合数据框

Q1 <- read.csv("Q1.csv")
Q2 <- read.csv("Q2.csv")
Q3 <- read.csv("Q3.csv")
Q4 <- read.csv("Q4.csv")

sales <- rbind(Q1, Q2, Q3, Q4)
```
注意使用 `rbind` 将每个数据框中的数据收集到一起。
值得一提的是，在这个案例中可以使用 `rbind`，因为所有四个数据框的结构都是相同的。
之前运行程序的结果是，`sales` 包含了每个数据框中的每一行。它没有为每个客户显示 `Q1`、`Q2` 等，仅仅是在文件底部为每一行数据创建新的行。因此，随着越来越多的数据被组合进去，文件变得越来越长。我们完全不清楚每个销售值发生在哪个季度。
我们的代码可以得到改进，从而为每条记录创建一个代表财务季度的列，如下所示：
```r
# 向数据框中添加季度列

Q1 <- read.csv("Q1.csv")
Q1$quarter <- "Q1"

Q2 <- read.csv("Q2.csv")
Q2$quarter <- "Q2"

Q3 <- read.csv("Q3.csv")
Q3$quarter <- "Q3"

Q4 <- read.csv("Q4.csv")
Q4$quarter <- "Q4"

sales <- rbind(Q1, Q2, Q3, Q4)
```
注意每个季度如何被添加到一个特定的 `quarter` 列。因此，当 `rbind` 将数据框组合成 `sales` 时，`sales` 就会通过季度列组织起来。
作为最后的点缀，让我们添加一个数值列，其中会标注高回报与常规回报：
```r
# 演示将销售标记为高价值

Q1 <- read.csv("Q1.csv")
Q1$quarter <- "Q1"

Q2 <- read.csv("Q2.csv")
Q2$quarter <- "Q2"

Q3 <- read.csv("Q3.csv")
Q3$quarter <- "Q3"

Q4 <- read.csv("Q4.csv")
Q4$quarter <- "Q4"

sales <- rbind(Q1, Q2, Q3, Q4)

sales$value <- ifelse(sales$sale_amount > 100, "High Value", "Regular")
```
注意最后一行代码在 `sale_amount` 大于 100 时分配「High Value」。在其他情况下，交易被分配为「Regular」。
